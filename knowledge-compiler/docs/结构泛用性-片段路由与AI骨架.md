# 结构泛用性：片段级路由 + AI 骨架 + 原文锚定

## 要解决什么

结构清晰的文档（教材）走正则建树已经很好；**结构不良的文档**（散文、扫抆件、
无样式 Word、扁平清单）要么丢光正文，要么产出没法看的扁平树。目标是让两种
情形都能出可用的知识树，且对好文档零额外成本。

## 实测发现（都是坐实的，不是推测）

| 现象 | 实测 | 后果 |
|---|---|---|
| 无标题纯散文 | `parse_md_to_nodes` 返回 **0 节点** | 正文**全部静默丢弃** |
| 编号清单 `1. 要点` | 每条被合成 `#` 标题 | 判"有结构"，产出 N 个平级根节点、无层级 |
| 分流条件 `split_mode in ('text',)` | 只有 TXT 可进 AI | **Word/PDF 永远进不了 AI 结构化**（模块文档却声称支持 Word） |
| 结构判定 | `标题数 ≥ 2` 的布尔值 | 无分级；只有 `####` 的文档被判"无结构" |
| 旧 AI 路径 | 每片只喂 6000/8000 字 | 约 25% 原文模型没看到 |
| 旧 AI 路径 | `max_tokens 2000` 输出 JSON 易截断 | 退化成"仅留前 10 段×500 字"，再次丢字 |
| 旧 AI 路径 | content 由模型**改写** | 原文表述丢失（对备考背诵是硬伤） |
| `txt_to_markdown` | 不识别已是 markdown 的 `#` 行 | 整份被并成一行，行结构与层级抹平 |

**关键标定发现**：真实教材的 OCR 产出**几乎每一行都是 `#` 标题**（`# (1) 含义。`
其实是正文被抬成标题）。真正的层级不在 markdown 深度里，而在**编号文本**里
（第X章 > 一、 > （一） > 1. > （1） > ①）。实测 37 个真实片段：标题占非空行
18.8%–33.7%，带编号的标题占 85%–95%。所以判分看**编号体系能否还原层级**，
而非标题多寡。

## 方案

```
每个片段（约 8000 字）独立判定
   │
   ├─ 结构可还原 → regex 建树（快、忠实、零调用）
   │
   └─ 结构不可还原 → AI 只出骨架 + 原文按区间锚定
                        │
                        └─ AI 不可用/骨架被拒 → 按段落分块保底
```

**三条设计约定**（都对应你选的"保真优先"）：

1. **AI 只出骨架，不写 content**。模型只回答"怎么分层"和"哪几段属于谁"，
   原文由程序按段落区间原样挂载。模型没有机会碰正文 → 不存在改写丢字。
2. **原文零丢失是硬性不变式**，任何路径都成立。`content_anchor.assert_no_content_loss`
   核验，测试里所有场景都必须 0 丢失。
3. **只对结构不良片段调 AI**。好文档零额外成本与延迟。

## 三个新模块

**`structure_score.py`** — 结构质量分级（0–1）+ 两条路由。
信号：可还原层级数、编号一致性、编号族丰富度、标题/正文平衡、噪声占比。
实测标定：真实教材 **0.75–0.97**，不良样本 **0.10–0.50**，阈值 0.60 落在中间。

**`skeleton_builder.py`** — AI 只输出标题骨架 + `src_range`（段落半开区间）。
严格校验：区间越界/倒置/非整数/深度超限一律整棵拒绝，交给重试与降级。
不合法时返回 None，绝不产出半成品。

**`content_anchor.py`** — 确定性锚定。每段归给「声明了它且层级最深」的节点，
天然避免父子重复；父节点自带引言段也能正确归属。区间不可信时退回按序/按比例
分配——**确定性、无损、绝不抛异常**。另有 `paragraphs_to_tree` 作为无骨架保底。

## 一并修掉的既有缺陷

- **无标题全文丢弃**：任何情况下都不再产出空树。无 AI key 时也按段落保留原文。
- **AI 路径丢字/易截断**：骨架机制天然不写 content，`max_tokens 2000` 截断
  问题不复存在。旧 `llm_structurer` 标注为已被取代（保留对照，主管线不再调用）。
- **`txt_to_markdown` 抹平行结构**：现在同时识别已有 markdown `#` 标题行
  （原样保留层级）与编号型标题行。实测：已是 markdown 标题的 .txt 从
  0.47（误判 skeleton）修到 0.83（正确走 regex）。
- **Word/PDF 进不了 AI 路径**：随新架构自然解决——片段级路由与文件类型无关，
  旧的 `split_mode in ('text',)` 过滤被整体取代。
- **旧 LLM 树无 `level` 因而永不被增强**：骨架产出的节点带 `level`，
  自动落入增强范围。

## 可视化

解析报告新增「结构判断」区：片段数、结构清晰度（平均/最低）、
几段走解析建树 / 几段走 AI 骨架 + 原文归位，以及原因（"层级不可还原"、
"标题占比过高"等）。字段为 `report.structure`，口径与 `parse_report` 一致。

## 取舍

- **保守优先**：骨架不可信就退回按序分配，宁可挂得不够准，也不丢原文。
- **父节点可自带引言**：按"最深者得"分配，兼顾"章节总起"这类写法。
- **深度上限 6 层**：超出视为契约违反、整棵拒绝（而非悄悄截断子树）。
- **阈值 0.60** 由实测标定，真实/不良之间有明显间隔（0.50 vs 0.75）。

## 测试

`test_structure_generalize.py`（50 断言）：评分分级、段落可逆、骨架响应严格
校验（含越界/倒置/非整数/深度超限）、锚定 5 种骨架形态**零丢字**、无骨架保底、
假 LLM 端到端、以及"无标题全文丢弃已堵死"的显式断言。

```bash
python knowledge-compiler/test_structure_generalize.py   # 回归
python knowledge-compiler/structure_score.py             # 评分标定（真实+合成样本）
```
