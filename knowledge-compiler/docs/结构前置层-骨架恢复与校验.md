# 结构前置层：文档骨架的恢复与校验（outline_skeleton）

## 要解决什么

解析过程中最昂贵的一类错误是**层级错位**：某主题的内容被挂到另一个主题下
（如「颜之推的教育思想」挂在「韩愈的教育思想」节点下）。事后审校（placement_audit）
只能修"能看见的错位"，而这类错位的根源发生在**节点出生之前**——没有任何一层
能修复一个"不存在的边界节点"。

## 根因（实测证据，数据来自 333 中教第三-五章）

1. **大纲标题丢失标记**：OCR/抽取输出里，`第四节 魏晋南北朝与隋唐时期的教育思想`
   是纯文本行（后跟一张图），而 `## 知识点一 颜之推的教育思想` 是标题。
   `parse_md_to_nodes` 只认 `#` 行 → 第四节节点从未创建 → 后续 知识点/内容 全部
   挂进上一节「第三节 隋唐时期的选士制度」。
   同一文档同一文本，6 月与 10 月两次运行结果不同（标题标记保留情况不同）→ 随机复发。
   同类实例：`第四节 汉代的教育思想`（董仲舒/王充同样错挂）、`第一节 魏晋南北朝时期的教育`。
2. **缺失的边界无人可见**：hierarchy_repair（编号栈）、LLM 层级校验（只调 level）、
   placement_audit（不移动结构节点）、structure_repair（只排序/改名）都只操作
   已存在的节点集；"知识点一…四 之后又出现知识点一"这类序列重启信号没有任何一层在查。
3. **改结构的阶段没有后置守卫**：LLM 层级校验重建整棵树后无校验（曾把
   「第三节 隋唐选士」弹成顶层独立根）；structure_repair 的改名只校验编号前缀
   相等（裸标题「第五章」可被改成「第五章 第一节 …」，吞掉一节标题）。
4. **页眉/导图文字污染结构**：重复页眉 `## 333 教育综合考研大纲知识清单（中国教育史分册）`
   （出现 4 次）成为节点，且以数字开头被误判为编号清单（arabic_dotted）；
   `第三章` 与内容框「知识导图」被错误合并成章标题，真章名被吞进正文。

## 方案：骨架优先（先立骨架，再挂内容；改骨架必过校验）

新增模块 `outline_skeleton.py`（纯确定性，无 AI 调用），两个入口共用一套不变式：

```
PDF→MinerU / Word / TXT
        │
        ▼
★【解析前置】normalize_markdown_outline(md_text, doc_hint)
   · 重复页眉剔除（与文件名有词面重叠、出现 ≥3 次的重复标题）
   · 章名补全（裸「第X章」+ 下一行真章名；正文里带章号的章名行回填）
   · 大纲标题恢复：纯文本「第X节/知识点X/第X章」行，满足
       序列位置吻合（= 上一编号 +1）、孤立（相邻行不是同类标题）、
       短行无句读、非目录（无 /页码）→ 提升为标题
       序列不吻合 → 判为页眉/导图文字/目录，忽略（不误提升）
       编号断档 → 记入 warnings（不猜标题）
        ▼
parse_md_to_nodes → adjust_standalone_levels → hierarchy_repair → build_tree
        ▼
★【解析/增强共用】audit_tree_skeleton(roots)
   · check_skeleton：同级节点序列不变量（章/节/知识点递增、不重复）
       - 知识点序列重启（<= 上一值）= 缺失边界的确定性证据（error）
   · repair_boundaries：重启处生成「（未识别小节）」占位节点，
     把其后条目整体移入（修父级，不再让内容错挂）
        ▼
LLM 层级校验（内部守卫：重建后骨架违规数增加则回滚）
        ▼
placement_audit（保留，降级为最后安全网）
        ▼
合并 _fix_hierarchy_and_merge
        ▼
★【增强前置】audit_tree_skeleton 再跑一次（合并/清理可能再破坏，
  在 structure_repair 之前把边界问题解决或记录）
        ▼
structure_repair（改名护栏：不得引入新的结构标题 token）
→ AI 增强 → cleanup → 输出
```

## 不变式（check_skeleton）

在**同一父节点下**按出现顺序检查：

| 家族 | 规则 | 违规类型 | 严重级 |
|---|---|---|---|
| 第X章 | 严格递增 | 重复 / 回退 / 跳号 | warn |
| 第X节 | 严格递增 | 重复 / 回退 / 跳号 | warn |
| 知识点X | 严格递增 | 重启（<= 上一值）| **error（可自动分隔）** |
| 知识点X | 严格递增 | 跳号 | warn |
| 知识点X | 章节下与节节点平级共存 | 疑似缺节边界 | warn |

## 修复与降级规则（保守，宁漏勿错）

- 标题文本存在 → 恢复标题（最高优先，测试证明 3 处真标题全找回、0 误收）。
- 序列重启但无标题文本 → 占位节点「（未识别小节）」+ 报告，不猜名字。
- 序列断档（如 第二 → 第四）→ 只告警，不插占位（后续内容父级未错，不造噪音）。
- 所有恢复/移动/告警都写入解析报告（数据面板「章节边界」区），无静默修改。

## 接入点

| 位置 | 改动 |
|---|---|
| `server._build_trees_from_md` | 解析前 normalize；建树后 audit；LLM 校验后再 check；结果随 tree_files 上报 |
| `tree_builder.build_single_tree` | 同上（脚本/调试路径） |
| `tree_builder.merge_split_chapter_titles` / `merge_chapter_titles` | 内容框标题（知识导图等）不参与章名合并 |
| `tree_builder.validate_and_repair_hierarchy` | 重建后骨架违规数不降则回滚 |
| `server._enhance_tree` | structure_repair 之前跑 audit_tree_skeleton；结果并进报告 |
| `hierarchy_repair` | 公开 `is_box_title()`；数字开头 >99 且空白分隔不视为清单编号（「333 …」页眉） |
| `structure_repair._rename_allowed` | 新标题不得引入额外「第X章节/知识点X」token |
| `parse_report.build_report` | 新增 `skeleton` 区块；upload 页数据面板渲染「章节边界」 |

## 验收用例（test_outline_skeleton.py）

1. 恢复：丢失的 `第四节 …`（纯文本）被提升，颜之推/韩愈落在其下；重复的同类行不提升。
2. 页眉：`333 教育综合…`（≥3 次）剔除；「逻辑框架 / 课后作业」等真框标题保留不下杀。
3. 章名：`第三章` + 纯文本章名合并；不再出现「第三章 知识导图」。
4. 占位：知识点序列重启（无标题文本）→ 生成「（未识别小节）」，子树整体跟随。
5. 守卫：改名不得吞并节标题；`333 …` 不再被当作编号。
6. 真实文件回归（存在时）：第四章含「第四节 魏晋南北朝与隋唐时期的教育思想」，
   颜之推/韩愈在其下；第三章含「第四节 汉代的教育思想」，董仲舒/王充在其下；
   错误级违规清零。
7. 幂等：normalize 两次结果一致。

## 不做的事（边界）

- 不改 placement_audit（继续做跨主题内容的安全网）。
- 不为 AI 骨架路径（结构不良文档）加前置——该路径本就由模型出骨架、原文锚定。
- 不猜缺失小节的名称（无文本时只放占位 + 报告）。

## v2 规则终稿（全链路测试驱动，2026-10-16）

破坏矩阵（21 模式 × 400 本）+ 全语料 + 全链路测试驱动出的最终规则：

**normalize（解析前置，迭代到不动点）**
1. Pass 0 标题内编号空格坍缩（"第 二 节" → "第二节"）；
2. Pass 0.5 紧邻重复标题行去重（OCR 双排/页眉残留，三连一次清干净）；
3. Pass 1 重复页眉剔除（与文件名词面重叠、≥3 次）；
4. Pass 2 章名补全（裸「第X章」+ 真章名；正文里带章号的章名行回填）；
5. Pass 3 标题提升（序列连续性驱动）：允许尾部句读（短标题、提升时去掉）、
   断 1 档（恰好丢过一个标题）按序列恢复并告警、**清单序列守卫**
   （连续段构成合法清单的才判为目录；残留块不误伤）。
   提升与清理相互影响 → 迭代到不动点，保证幂等。

**repair（解析/增强前置共用的骨架审计）**
- 节内知识点序列重启 → 占位「（未识别小节）」**提升为该节的兄弟**（缺的是节）；
- 章下直挂知识点（该章还有节，或序列出现重启）→ 按重启切分逐段包占位，与节同级；
- 同号同名知识点（重复行）→ 只记 duplicates，不产生占位。

**守卫（防再次破坏）**
- LLM 层级校验：重建后骨架违规数不降则回滚；
- structure_repair 改名：不得引入新的结构 token；
- 合并阶段：内容框标题不参与章名合并；
- hierarchy_repair：超大数字+空格（页眉）不视为编号。

**验收**：21 模式 × 400 本全过；37 份语料全链路零错误级违规。历史报告记录纯解析
全链路中位约 8ms/份、前置层中位约 5ms/份；完整报告保存在本地归档区，不随仓库发布。

## 后续：AI 提案式复核（设计，待实施）

确定性层负责"结构可判定"的一切；剩余不可判定场景适合加一层 AI 复核：

- **位置**：增强前置（与确定性审计串联，在 structure_repair 之前）；
- **输入**：只发送"有缺口的东西"——占位节点、骨架告警、可疑归属组
  （含标题与首段正文做上下文），发送全量父组仅在显式开关时；
- **输出**（严格 JSON）：占位命名提案 / 归属提案 / 分类提案；绝不改写正文；
- **应用护栏**（全部满足才采纳，否则原样保留并记报告）：
  不增删节点、同级不变量违规数不增加、同章约束、结构 token 不变、
  正文零改动；应用前快照，任一校验失败即回滚；
- **预算**：单树 ≤ N 次调用（仅处理缺口项），失败降级为"占位保留 + 报告"；
- **测试**：离线 mock 覆盖 采纳/拒绝/回滚 三条路径。

## v3 规则（容器族与平级标题，2026-10-16 二次复盘）

问题截图（察举制度区域）暴露出更普遍的一类：**容器/平级标题没有被当作真实
结构节点**。修复分三块（引擎层 hierarchy_repair / tree_builder）：

1. **容器族识别**（hierarchy_repair.NUMBER_PATTERNS 新增三族，与编号知识点同级）：
   - `知识点 X`（无编号容器，如「知识点 察举制度」「知识点 汉代的文教政策」）
     —— 此前是"普通文本节点"：会被上部内容框吸附（挂进精华提要）、
     且被（一）（二）穿透成同级兄弟；现在它是编号知识点一样的容器，
     （一）/丹丹攻略/（二）/1./2. 全部正确归属。
   - `考点 N …`（《核心考案》式：考点 24 必然和偶然…）
   - `考点 X`（无编号变体）
2. **平级独立标题不互相嵌套**：连续的无编号标题若 hash 深度相同，是"平级"
   （挂到最近的编号/结构父级下），不再链式互套（修复「考点 24 > 考点 25 >
   考点 26」深链）；hash 更深（## + ###）保持原来的嵌套语义。
   仅对真实解析节点（带 src_hash）生效，合成/存量数据语义不变。
3. **拆分容器标题合并**：裸「知识点」/「考点」标题 + 下一行名称
   （OCR 拆行，如「知识点」+「学习动机的培养与激发」）→ 合并为
   「知识点 学习动机的培养与激发」容器（与「第X章」+章名合并同一机制）。

新增测试：破坏矩阵 +2 模式（unnumbered_kp_containers / exam_point_style，
23 模式 × 400 本全过）；语料已知案例 +2（c3986895 察举容器、31825f95 考点平级）。
