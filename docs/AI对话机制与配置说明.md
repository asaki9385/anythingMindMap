# AnythingMindmap AI 对话机制与配置说明

> 最后更新：2026-10-20  
> 适用范围：AI 对话页、对话复习组件、学习模式、追问模式、知识补全  
> 依据：当前工作区代码与真实模型联调结果，而非产品设想

---

## 1. 结论摘要

AnythingMindmap 的 AI 对话由两套机制组成：

1. **学习模式（learn）**
   - 用户主动提问。
   - 系统先从当前知识树做结构检索，再组装接地上下文。
   - 模型依据资料讲解；资料未覆盖时允许做有标识的逻辑推导。
   - 可选开启「知识补全」，用通用学科知识补充，但必须标注 `【AI 补充】`。
   - 不判分、不记录复习进度。

2. **追问模式（probe）**
   - AI 按知识点出题，用户凭记忆回答。
   - 模型先输出隐藏诊断 JSON，再流式说出自然回应。
   - 代码负责真实回忆轮次、提示阶梯、止损、过关和长期复习调度。
   - 用户在考测中提出理解性问题时，可临时进入 `clarify` 答疑，不扣回忆轮次。
   - 会话状态和复习进度会落盘，服务重启后仍可续接。

当前对话页还提供：

- 学习 / 追问切换；
- 当前知识库切换；
- 回复风格、思考强度、引用偏好、回答语言、自定义指令；
- 知识补全开关；
- 章节引用、流式回答、回到底部、左栏简略状态。

## 2. 系统结构

```text
浏览器 AI 对话页
  ├─ client.js
  │   ├─ 场景、当前资料、左右栏
  │   ├─ 对话偏好持久化
  │   └─ 左栏状态：kt-review-activity
  │
  └─ review_widget.js
      ├─ 学习模式 UI / 追问模式 UI
      ├─ NDJSON 流式解析
      ├─ 章节引用、知识补全、个性化参数
      └─ 消息、滚动、状态事件

FastAPI server.py
  ├─ /api/review/learn     学习模式
  ├─ /api/review/units     复习单元预览
  ├─ /api/review/start     开始追问会话
  ├─ /api/review/answer    提交回答
  ├─ /api/review/skip      跳过当前考点
  ├─ /api/review/end       主动结束
  ├─ /api/review/status    查询会话
  └─ /api/review/progress  复习进度

review_engine.py
  ├─ 知识树 → 复习单元
  ├─ 学习模式锚点检索与上下文组装
  ├─ 原生多轮 messages 构造
  ├─ 学习 / 判分 / 自然话语提示词
  ├─ JSON 先行诊断、流式话语拦截
  ├─ 状态机、提示阶梯、止损、临时答疑
  └─ ReviewStore 进度持久化

app_settings.py
  └─ 模型服务商解析、请求头、统一请求参数
```

### 2.1 模型调用方式

所有 AI 对话都走 OpenAI Chat Completions 兼容接口。学习模式现在是**原生多轮消息数组**，不再把历史硬拼成一段“学习者 / 老师”文本：

```json
{
  "model": "当前配置模型",
  "messages": [
    { "role": "system", "content": "系统规则 + 资料上下文 + 较早对话压缩摘要" },
    { "role": "user", "content": "较早的问题" },
    { "role": "assistant", "content": "较早的回答" },
    { "role": "user", "content": "本轮问题 + 回答偏好" }
  ],
  "stream": true,
  "temperature": 0.55,
  "max_tokens": 2400,
  "reasoning_effort": "none"
}
```

当前实现特点：

- 学习和追问都使用真实 `user` / `assistant` 角色消息。
- 最近两轮对话（最多 4 条消息）完整保留，不再按 300 字符硬截断。
- 更早轮次由服务端压成确定性摘录，放入 system 的「较早对话脉络」。
- 流式输出通过 FastAPI NDJSON 转发给前端。
- 若网关不支持流式，或流式响应为空，会自动退回普通 JSON 请求。
- 请求失败会重试；仍失败时，学习模式显示错误说明，追问模式退回确定性话术和兜底判分。

### 2.2 模型服务解析优先级

`app_settings.resolve_chat()` 的优先级为：

1. 本次请求显式传入的 Key / Base URL / Model。
2. 设置页保存的当前默认服务商。
3. 环境变量 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`MODEL`。
4. 无可用模型。

服务商配置保存在本机 `knowledge-compiler/data/settings.json`，前端只回显脱敏 Key。本文档不记录任何实际密钥。

## 3. 学习模式（learn）

### 3.1 使用场景

- 用户自由提问。
- AI 依据当前资料讲解。
- 不判分，不进入复习状态机。
- 适合「解释概念」「梳理章节」「对比知识点」「让 AI 补全理解」等场景。

### 3.2 请求过程

```text
用户输入问题
  ↓
POST /api/review/learn
  ↓
读取当前知识树
  ↓
根据章节 / 问题关键词检索锚点
  ↓
补充父级、子节点、相邻兄弟、跨章节关联
  ↓
组装最多约 7000 字符的资料上下文
  ↓
构造原生 system + user/assistant 消息数组
  ↓
流式调用模型
  ↓
返回回答 + 确定性书内出处
  ↓
前端渲染回答、出处和「含 AI 补充」标识
```

### 3.3 上下文检索策略

`build_learn_context()` 当前**不是向量检索，也不是联网搜索**，而是关键词、标题路径与轻量关联召回：

1. 问「这本书 / 全书 / 整体框架 / 全书目录」时，忽略当前浏览章节，直接使用「全书导学 + 全部顶层章节 + 章节摘要」的全书概览上下文。
2. 其他问题有当前章节时，优先匹配章节标题。
3. 无章节或章节未命中时，从问题中提取 2–4 字关键词。
4. 去掉「什么、怎么、为什么、主要、区别」等停用词。
5. 按标题、摘要、关键词、正文等匹配情况为节点打分。
6. 选择最相关的锚点，并补充：
   - 父级语境；
   - 锚点节点自身；
   - 直接子节点；
   - 同一父节点下的相邻兄弟节点（便于对比辨析）；
   - `related_node_ids` / `related_titles` 显式关联（如果节点提供）；
   - 其他章节中词面相关、且有内容的节点（最多 2 个）。
7. 章节模式下从章节入口 BFS 展开近处结构，同时保留跨章关联节点。

上下文内容包括：

- 书名；
- 当前章节或相关路径；
- 结构纲要；
- 节点摘要；
- 关键词；
- 考点；
- 正文内容；
- 最多约 18 个内容块；
- 上下文总长度上限约 7000 字符。

### 3.4 书内出处

书内出处由服务端检索结果确定性生成，不交给模型编造。

- 检索到的节点路径组成 `sources`，最多 6 条。
- `related_sources` 单独记录跨章节关联路径。
- 前端只显示路径末两级。
- 相同路径去重。
- 引用偏好限制展示数量：
  - 精简：1 条；
  - 自动：3 条；
  - 强调：4 条。

### 3.5 多轮历史与压缩策略

学习模式前端在 `learnMsgs` 中保存对话，发送请求时取最近 16 条（不含本轮问题）。

服务端 `build_learn_messages()` 再做一次窗口处理：

- 最近 4 条消息（最多两轮）完整保留，不截断。
- 更早的消息压缩为 `【较早对话脉络（压缩）】`，每条最多约 260 字。
- 压缩摘要放入 system 上下文，真实近期消息仍作为独立 `user` / `assistant` 消息发送。
- 当前资料放在 system；本轮问题、回答约束和偏好放在最后一条 `user`。
- 学习会话仍只在浏览器内存中保存，刷新页面不会恢复完整对话。

## 4. 知识补全

### 4.1 定义

「知识补全」不是联网搜索，也不会访问网页。

它的作用是：

> 在当前资料未覆盖某部分内容时，允许模型使用通用学科知识补充，以形成更完整的理解。

### 4.2 防误导规则

补全模式强制区分：

- **资料依据**：资料中明确出现过、可由资料支撑的内容。
- **AI 补充**：资料未覆盖、来自通用知识的内容。

并要求：

- AI 补充必须放入明确的 `【AI 补充】` 段落。
- 不得为补充内容编造书内出处。
- 不得声称补充内容来自资料。
- 不确定内容应使用「通常 / 可能」等措辞。
- 回答气泡底部显示「含 AI 补充」标识。

### 4.3 开关状态

- 默认关闭。
- 仅在学习模式可用。
- 开关状态不持久化，切换资料或刷新页面后回到关闭。
- 打开时输入框占位符会变为「提问；资料不足时由 AI 补全…」。

### 4.4 未开启补全时的边界

默认模式不再机械回复「资料里没有提到」。它会：

- 讲清资料明确写到的内容；
- 对可由资料合理推出的逻辑桥梁，标明「基于资料可以推出」；
- 对真正超出资料范围的内容，说明「这部分当前资料没有展开」，并可提示开启「知识补全」；
- 不补写具体事实，也不伪造出处。

## 5. 追问模式（probe）

### 5.1 使用场景

- AI 按章节或全书出题。
- 用户凭记忆作答。
- AI 先诊断回答覆盖、缺口和混淆，再给出自然回应。
- 卡住时给提示；提示失败后讲解并换点。
- 适合背诵、回忆、章节复习和长期间隔复习。

### 5.2 复习单元如何生成

知识树节点会转换为「复习单元」：

- 一个节点有 **2–8 个子节点**，可作为单元；
- 或有考点标注的叶子节点，可作为单元；
- 选中一个单元后，会屏蔽其后代，避免父子重复考；
- 单册包装层会自动展开；
- 默认一轮最多 40 个单元；
- 预览接口最多可返回 300 个单元，硬上限 1000；
- 可选范围：
  - 全书；
  - 指定章节；
  - 薄弱点 / 待复测；
  - 高频考点；
  - 指定单元 ID。

### 5.3 隐藏状态机

每个考点在代码中维护：

| 字段 | 含义 |
|---|---|
| `turn_count` | 真实回忆轮次；`clarify` 不计入 |
| `hint_count` | 已给提示次数 |
| `levels` | 历次真实作答层级 L0–L4 |
| `independent_answers` | 无提示下的作答次数 |
| `prompt_had_hint` | 当前提示是否带过提示 |
| `awaiting` | `answer` / `restate` / `h4_restate` |
| `trap_list` | 易混点 |
| `trap_resolved` | 易混点是否已澄清 |
| `clarify_count` | 当前考点已答疑次数，最多 2 次 |
| `h4_used` | 是否已给过完整答案 |
| `status` | `pending` / `passed` / `half` / `failed` |

这些值不会直接显示给用户。

### 5.4 判定等级

模型先输出隐藏诊断 JSON，其中等级为五级：

- `L0`：空白；
- `L1`：零星关键词；
- `L2`：有点无框架；
- `L3`：完整骨架；
- `L4`：能迁移。

代码再结合以下因素决定是否过关：

- 是否达到 L3/L4；
- 该次回答是否有提示辅助；
- 应含条目是否覆盖完整；
- 是否存在未澄清的易混点。

### 5.5 先诊断、后说话

追问判分采用两段式协议：

```text
第一行：单行紧凑诊断 JSON
第二行：###SAY###
第三行起：自然语言回复
```

服务端在收到 `###SAY###` 之前不向前端转发文本，只静默缓存诊断段；检测到分隔符后，才把后续自然语言流式推给前端。这样模型在开口前已经写出：

- `gaps`：没说到的内容；
- `confusions`：易混点；
- `next_action`：下一步动作；
- `hint_level`：本次提示级别。

旧协议（先说话、后 `###JSON###`）仍保留解析兼容，但新请求使用 JSON 先行格式。

### 5.6 临时答疑 `clarify`

当学习者不是作答，而是在问「为什么 / 怎么理解 / 两者什么关系 / 我没懂」时：

- 明确疑问句由代码识别，直接进入 `clarify`；
- 非显式问句也可由判分 JSON 的 `next_action: "clarify"` 触发；
- 每个考点最多 2 次；
- 不增加 `turn_count`，不写 `levels`，不进入卡壳止损；
- 回答 2–4 句概念解释，可使用类比和场景；
- 结尾自然邀请学习者回到原问题；
- 不直接揭晓整题应含条目。

### 5.7 提示与止损

- 单考点提示最多 2 次。
- 提示规则：
  - H1：场景锚点 / 对比 / 反例；
  - H2：对立概念 / 结构位置 / 挖空提示；
  - H3：关键词或首字锚点（作为规则保留，当前上限通常只用到 H1/H2）。
- 「想不起来 / 不知道 / 给点提示」按求助处理，不计回忆轮。
- 提示用尽仍不会，或用户跳过，会讲解答案并换点。
- 主要止损条件：
  - S1：提示耗尽仍卡住；
  - S2：连续两轮 L0/L1；
  - S3：单考点真实回忆轮达到 6；
  - S4：用户主动跳过或放弃。
- 答案泄漏检测会拦截提示中意外出现的答案核心内容。

### 5.8 过关与复述

若用户第一次就达到过关条件，系统可能再要求一次无提示完整复述；复述通过后状态才最终落定。

### 5.9 长期复习调度

复习进度由 `ReviewStore` 保存：

- 通过：进入复测队列，间隔按 `1 → 2 → 4 → 7 → 15 → 30` 天递增；
- 提示辅助过关：记为 `half`，次日再练；
- 未过关：记为 `failed`，立即重新到期并优先复练。

进度文件：

```text
knowledge-compiler/data/review/<file_key>/progress.json
knowledge-compiler/data/review/sessions/<session_id>.json
```

追问会话内存中保存，磁盘也有快照；服务重启后可通过 `ReviewSession.from_state()` 恢复。

## 6. 对话设置与个性化

当前对话偏好保存在浏览器 `localStorage`：

```text
kt-chat-prefs
```

| 设置 | 默认值 | 可选值 | 当前实际作用 |
|---|---:|---|---|
| 回复风格 | 自动 | 简洁 / 自动 / 详细 | 修改提示词，并调整最大输出 token |
| 思考强度 | 标准 | 快速 / 标准 / 深入 | 修改提示词、temperature、输出预算；支持的网关开启真实推理 |
| 引用偏好 | 自动 | 精简 / 自动 / 强调 | 修改提示词，并控制前端出处数量 |
| 回答语言 | 中文 | 中文 / 中英术语 | 中文为主，关键术语可附英文 |
| 自定义指令 | 空 | 最多 300 字 | 追加表达偏好，但不能覆盖资料依据和安全约束 |

### 6.1 学习模式输出预算

学习模式从基础 1600 tokens 起算：

- 回复风格：
  - 简洁 `-260`
  - 自动 `0`
  - 详细 `+800`
- 思考强度：
  - 快速 `-180`
  - 标准 `0`
  - 深入 `+3000`（为隐藏推理和可见回答同时预留）
- 知识补全：额外 `+220`

最终限制在 `420–6400` tokens。

temperature：

- 快速：0.5；
- 标准：0.55；
- 深入：0.65。

### 6.2 关于「思考强度」

「思考强度」现在同时影响两层：

1. **产品层**
   - 提示词：是否要求推导摘要、适用条件、边界和易错点；
   - 输出预算；
   - temperature。

2. **模型层（受服务商能力约束）**
   - 内置 opencode 网关在「深入」时发送 `reasoning_effort: "medium"`；
   - 其他档位发送 `reasoning_effort: "none"`；
   - 其他 OpenAI 兼容端点若未确认支持该字段，不会强行发送，避免 400；
   - 对这类端点，「深入」仍主要依靠提示词、温度和输出预算。

系统只展示可核验的推导摘要，不要求或展示隐藏思维链。

### 6.3 追问模式输出预算与 temperature

- 判分 / 回应：
  - 标准 1100 tokens；
  - 深入 4000 tokens；
  - 深入时 temperature 0.6，其余 0.35。
- 代码驱动话语（开场、提示、讲解、过渡、收尾）：
  - temperature 0.7；
  - 深入时若网关支持，发送低档 reasoning。

### 6.4 适用范围

这些偏好同时进入：

- 学习模式；
- 知识补全；
- 追问模式的判分与自然语言生成；
- 追问的临时答疑。

追问开始时，前端把当前 `prefs` 一并发送给 `/api/review/start`；会话落盘时保存偏好，恢复会话后继续使用。

### 6.5 学习 / 追问模式

模式保存在：

```text
kt_review_mode
```

可选：

- `learn`：学习模式；
- `probe`：追问模式。

左侧「对话助手」栏中的模式切换会同步到 ReviewWidget 和本地存储。

## 7. 左栏状态与界面行为

### 7.1 AI 状态

对话组件通过自定义事件向父页面广播：

```text
kt-review-activity
```

事件字段：

```json
{
  "phase": "idle | thinking | done",
  "detail": "正在检索原文并组织回答…",
  "mode": "learn",
  "file": "demo_calculus.json",
  "chapter": ""
}
```

左侧「对话助手」栏会将其压缩成简短状态，例如：

- 已就绪；
- 正在读取资料；
- 正在检索原文；
- 正在评估回答；
- 回答已完成；
- 本轮未完成。

该状态不是模型的隐藏思维链，只是确定性的流程阶段提示。

### 7.2 消息滚动

- 用户停留在底部时，流式回答自动跟随。
- 用户向上滚动后，锁定当前阅读位置。
- 当离开底部时显示「回到底部」箭头。
- 点击箭头后平滑回到底部并恢复自动跟随。

### 7.3 章节引用

- 点击回形针按钮展开当前资料的章节列表。
- 再次点击收起。
- 缓存为空时现场调用 `/api/review/units` 获取章节。
- 选择章节后向输入框插入 `@章节名`，作为对话上下文提示。

### 7.4 当前知识库切换

左侧「当前知识库」卡片可展开知识库列表；切换后同步更新：

- 当前文件；
- 页面 Hash；
- 对话上下文；
- 左右栏资料；
- 引用来源；
- 相关知识点；
- 页面标题。

## 8. 流式 API 与返回格式

### 8.1 NDJSON 流

服务端返回格式：

```text
{"t":"d","text":"增量文本"}\n
{"t":"d","text":"更多文本"}\n
{"t":"snap","data":{...最终快照...}}\n
```

错误：

```text
{"t":"err","error":"错误信息"}\n
```

前端按行解析：

- `d`：增量渲染；
- `snap`：最终落库并替换临时流式气泡；
- `err`：显示错误。

追问模式下，`d` 事件只包含 `###SAY###` 之后的自然语言，不包含诊断 JSON。

## 9. 系统提示词原文

以下内容与当前 `review_engine.py` 保持一致。

### 9.1 学习模式：资料接地

```text
你在给考研学生做辅导，像一位有经验、会顺着学生思路讲下去的老师。
只依据用户给出的【资料】回答：资料里明确写到的概念、人物、观点，要依据资料讲清楚；绝不编造具体事实或出处。
先判断问题意图，再组织语言：
- 问“是什么/有哪些/包括什么”时，用清晰的结构化要点作答；
- 问“为什么/怎么理解/有什么区别/有什么联系”时，先用 1–2 句直觉、类比或场景破题，再沿着因果链展开，少用冷冰冰的列表；
- 需要推导时，可以说明“基于资料可以推出”的逻辑桥梁，但不要把合理推导说成资料原文。
如果确实超出当前资料范围，要明确说“这部分当前资料没有展开”，并可以自然提示学习者可开启【知识补全】做学科背景延展；不要因为资料没直接写就机械终止对话。
讲完一个核心或易错概念后，如果上下文合适，可以在结尾顺势抛出一个简短的思考题或应用场景（微追问），引导对话继续；不要每轮都强行提问。
不要输出“参考、出处、来源”之类的行——出处由系统自动附上。
```

### 9.2 学习模式：知识补全

```text
你在给考研学生做辅导，像一位有经验、会顺着学生思路讲下去的老师。
优先依据用户给出的【资料】回答，资料里明确写到的概念、人物、观点要依据资料讲清楚。
按问题意图组织表达：事实梳理类用清晰要点；“为什么/怎么理解/区别/联系”类先用直觉、类比或场景破题，再展开逻辑链，避免只罗列短句。
资料没有直接覆盖、但学习者确实需要的内容，可以用你已有的通用学科知识补全；补全时必须区分：
1. “资料依据”：资料中明确写过、可由资料支撑的内容；
2. “AI 补充”：资料未覆盖、基于通用知识补充的内容。补充内容要单独用“【AI 补充】”标注。
不能把 AI 补充内容说成资料原文；不得为补充内容编造资料出处。对不确定的信息使用“通常/可能”等措辞。
讲完一个核心或易错概念后，如果上下文合适，可在结尾提出一个简短的思考题或应用场景，但不要每轮都追问。
不要输出“参考、出处、来源”之类的行——书内出处由系统自动附上。
```

### 9.3 追问模式：诊断与回应

```text
你是复习陪练，和学习者进行连续的一对一对话。你必须先完成内部诊断，再开口说话。

输出格式（严格遵守，不要 Markdown 代码围栏，不要额外解释）：
第一行只输出一个紧凑 JSON：
{"level":"L0空白|L1零星关键词|L2有点无框架|L3完整骨架|L4能迁移","matched_points":[命中条目编号，从0起],"gaps":["没说到的"],"confusions":["易混点"],"trap_resolved":false,"asks_for_answer":false,"next_action":"clarify|probe|restate|hint","hint_level":"H1|H2|H3|null"}
第二行只输出 ###SAY###
第三段才是说给学习者听的自然语言。

诊断与话语规则：
- 先根据学习者最新回答和前面的对话，判断命中、缺口、混淆，再决定下一句话；不要先安慰再临时找缺口。
- 不整段背要点原文；不提回合/提示次数/层级代号/过关判定。
- level 为 L0/L1 且 next_action=hint 时，回复必须给出当前允许的提示，并将 hint_level 填成该级别。
- 如果学习者是在追问概念、问“为什么/怎么理解/二者关系”，而不是在回忆作答：next_action 填 clarify。先讲清 2–4 句，再自然邀请他回到原问题；不要给出应含条目的完整答案，不要扣回忆轮次。
- 如果学习者卡住、放弃、索要答案，或确实没有更多可挖：直接讲清框架并收尾，不强行追问。
- 如果还有可挖但暂不需要提示：一次只问一个真正能推进思考的问题。
- {hint_line}
```

其中 `{hint_line}` 由代码动态替换为当前允许的提示级别，例如：

```text
本轮最多只能给 H1（场景锚点：用对比、反例或应用场景把注意力引向考点，不透露条目内容）。
```

或：

```text
提示已给过两次，不要再给提示。
```

### 9.4 追问模式：自然话语生成

用于开场、提示、讲解答案、过渡、复述邀请、收尾、临时答疑：

```text
你是复习陪练，说话像真人老师：自然、口语化、有来有回，通常 1–3 句，必要时可稍展开。不报内部进度，不提层级代号，不机械加粗关键词。只输出要说的话本身。
```

### 9.5 提示规则

```text
H1：场景锚点——用对比、反例或应用场景把注意力引向考点，不透露条目内容。
H2：对立概念/挖空提示——点出相对机制、结构位置或给一个起始词，让对方自己补全。
H3：锚点提示——给一个关键词或首字让对方往下接。
```

## 10. 业务提示词如何组装

### 10.1 学习模式 messages

`build_learn_messages()` 的结构：

```text
system:
  {资料接地或知识补全系统提示}
  【资料】
  {检索上下文，最多约 7000 字符}
  【较早对话脉络（压缩）】
  {超过最近两轮的更早消息摘录}

messages:
  {最近 4 条 user / assistant 消息，完整保留}
  user:
    【本轮问题】
    {用户问题}

    回答约束：
    {资料接地 / AI 补充规则}

    【回答偏好】
    回复风格：...
    思考强度：...
    引用偏好：...
    回答语言：...
    自定义表达偏好：...
```

`build_learn_prompt()` 只作为调试和兼容用的扁平视图；实际模型调用使用 `build_learn_messages()` 的原生消息数组。

### 10.2 追问判分 messages

`build_judge_messages()` 的结构：

```text
system:
  {JUDGE_SYSTEM}
  【本轮考点】{unit.title}
  应含条目（编号从 0 起）：...
  状态（勿提及）：第 N 轮，已提示 X 次；
  上次缺口：...；易混：...；提示规则；答疑次数
  【个性化表达偏好】

messages:
  {最近 10 条真实 user / assistant 对话}
  user:
  {学习者最新回答}

  【本轮输出协议（硬约束）】
  先输出诊断 JSON，换行输出 ###SAY###，之后才输出对学习者说的话。
```

### 10.3 自然话语

`llm_say()` 根据业务类型生成不同 user prompt：

| 类型 | 用途 |
|---|---|
| `open` | 开场提问 |
| `hint` | 按提示阶梯给线索 |
| `explain` | 讲清答案 |
| `clarify` | 回答理解性反问并带回原题 |
| `transition` | 自然换到下一考点 |
| `restate` | 邀请完整复述 |
| `wrap` | 本轮收尾 |

## 11. 错误、降级与安全边界

### 11.1 学习模式降级

- 未配置模型：提示去设置页配置服务商。
- 模型无返回：提示稍后重试或测试服务商。
- 流式响应为空：自动退回非流式请求。
- 前端保留错误消息气泡。

### 11.2 追问模式降级

- 判分 JSON 解析失败：自然回复可保留，判定信号使用确定性兜底。
- 诊断段与话语段格式异常：兼容旧 `###JSON###` 协议。
- 自然话语失败：使用内置话术模板。
- 会话仍可继续。
- 存储失败只打印警告，不中断对话。

### 11.3 防止答案泄漏

追问模式会检测提示和回应中是否意外包含应含条目核心内容；疑似泄漏会被替换为安全追问话术。

临时答疑 `clarify` 不受同一条“回忆提示”泄漏规则限制，但仍要求：

- 讲概念，不整段罗列本题应含条目；
- 不把解释变成直接公布完整答案；
- 结尾带回原问题。

### 11.4 知识补全的边界

知识补全允许通用知识补充，但仍要求：

- 不伪造资料出处；
- 明确标注 AI 补充；
- 不确定内容显式表达不确定性；
- 自定义指令不能覆盖资料依据和标注约束。

## 12. 当前已知限制

1. **不是向量 RAG**：检索依赖章节标题、关键词、兄弟节点、显式关联与词面相似度，不理解深层语义。
2. **不是联网搜索**：知识补全只使用模型通用知识，不访问网页。
3. **学习对话不持久化**：刷新页面会丢失当前学习会话消息。
4. **学习历史压缩是确定性摘录**：不是额外调用模型生成语义摘要；最近两轮完整，较早轮次为限长摘录。
5. **真实 reasoning 受服务商支持范围约束**：内置 opencode 网关会按档位发送 `reasoning_effort`，其他端点可能只使用提示词和输出预算。
6. **右侧「引用来源」不是逐条答案引用**：该面板目前展示基于章节列表的展示性来源；回答底部的出处 pill 才来自本次检索路径。
7. **上下文长度是估算值**：模型卡片中的 token 环使用文件大小或节点数估算，不等同于真实 tokenizer 结果。
8. **没有取消流式请求的独立接口**：关闭/切换页面会停止展示，但不保证中止上游 HTTP 请求。
9. **没有单独的对话历史列表**：追问会话可由 session 恢复，但学习对话没有历史记录管理。
10. **深档输出可能较慢且成本更高**：真实推理 token 与可见回答共用预算，所以深档的 `max_tokens` 明显提高。
11. **追问偏好变更不热更新到已开始会话**：会话开始时保存偏好；要立即应用新设置，建议重新开始一轮。

## 14. 快速流程版

### 学习模式

```text
提问
→ 章节/关键词检索
→ 父级 + 子节点 + 兄弟 + 跨章关联
→ 资料上下文（≤7000 字）
→ 最近两轮完整 + 更早轮次压缩
→ 原生 user / assistant 多轮 messages
→ 资料接地回答 / 可选 AI 补充
→ 流式输出
→ 确定性书内出处
→ 前端显示回答与来源
```

### 追问模式

```text
选范围（携带个性化偏好）
→ 知识树生成复习单元
→ AI 出题
→ 用户回答
→ 若是理解性反问 → clarify 答疑（不扣轮次）
→ 否则隐藏诊断 JSON → ###SAY### → 流式自然回应
→ 提示/复述/换题/过关
→ 记录复习进度与下次到期
→ 长期间隔复习
```
