# 统一配置中心

> 目标：**一次配置，全局生效**。模型服务、MinerU Token、学科设置集中一页；上传处理、对话复习、AI 增强、结构化全部自动取用，不再逐页询问。

## 一、三类配置

| 配置 | 说明 |
|---|---|
| **模型服务** | 任意 **OpenAI chat-completions 兼容**端点，可存多套、一套设为默认。DeepSeek、opencode、OpenRouter、Kimi、GLM、硅基流动、通义……或自定义粘贴 Base URL |
| **MinerU Token** | PDF 云端 OCR；不配置自动回退 PyMuPDF 本地提取 |
| **学科设置** | 科目名 / 考试名，决定 AI 标注考点时的参照标准（默认 教育学 / 333教育综合考研）|

## 二、解析优先级（四个 LLM 调用点统一）

```
本次请求显式参数（上传页/复习页的"本次覆盖"）
  > data/settings.json 统一配置（默认服务商）
    > 环境变量（OPENAI_API_KEY / OPENAI_BASE_URL / MODEL / MINERU_TOKEN）
      > 无 → 优雅降级（增强跳过 / 复习走离线兜底判分）
```

调用点：节点增强（node_enhancer）、章/全书导学（node_enhancer）、无结构文本结构化（llm_structurer）、复习判分（review_engine）。

### 凭证配置

仓库不内置任何 API Key 或 MinerU Token。请在设置页保存服务商，或通过环境变量配置。
未配置模型或 MinerU 时，系统走优雅降级：

- 没有模型：跳过 AI 增强/导学，复习判分使用确定性兜底；
- 没有 MinerU：PDF 使用 PyMuPDF 提取（仅对带文字层的 PDF 有效）。

### 网关兼容：请求头与请求体扩展（`chat_headers` / `chat_body_extras`）

不同网关除了 `Authorization` 之外还可能要额外的东西。**所有 chat-completions 调用点
统一走这两个函数构造请求，不要在调用点各写一份**（目前 11 个调用点已全部接入）：
`node_enhancer` ×4、`structure_repair`、`review_engine`、`parser/llm_structurer`、
`tree_builder`、`server._enhance_tree` 健康检查、`app_settings.test_chat`、`benchmark_enhance_speed`。

opencode 的 Go 网关（`https://opencode.ai/zen/go/v1`）有两条实测出来的硬要求：

| 项 | 内容 | 不加的后果 |
|---|---|---|
| `x-opencode-session` 头 | 客户端的会话标识（本进程固定一个 `kt-<hex>`） | 一律 **HTTP 400 MissingSessionID**，请求根本进不去 |
| `reasoning_effort: "none"` | 关掉"思考" | 网关在多后端间动态路由，同一模型同一提示词有时思考 0 token 直接作答（~550 token / 5s），**有时思考 1000+ token 把 `max_tokens` 吃光 → JSON 被截断 → 解析失败 → 整批节点静默走兜底摘要** |

`reasoning_effort="none"` 是**给不稳定的路由兜底**，不是"推理模型专用"——实测非推理的
`glm-5.3-flash` 在这个网关上同样偶发进入思考模式。实测关掉后 `deepseek-v4.1-flash`
与 `glm-5.3-flash` 各 3 轮 × 2 节点全部增强成功（6/6），输出稳定在 ~550 token，
`max_tokens=1000` 够用，无需再调大上限。

## 三、安全

- 设置页保存的密钥只落本机 `data/settings.json`（随 `data/` gitignore）。**所有 API 响应一律脱敏**（`sk-abc****wxyz`），前端永远拿不到明文；
- 默认只监听 `127.0.0.1`；CORS 默认同源，跨域需显式配置 `CORS_ORIGINS`；
- 设置 `KT_AUTH_PASSWORD` 后启用 HTTP Basic Auth（`KT_AUTH_USER` 默认 `admin`），`/api/health` 不拦截；
- 编辑服务商时 Key 留空 = 不修改，填写 = 覆盖；
- 检测到浏览器 localStorage 里存有旧版配置（上传页 `kt-api-config`、复习页 `kt-deepseek-key`）时，设置页会提示**一键导入**。

## 四、Base URL 归一化

填 `…/v1`、裸域名或完整地址都可以，保存时自动补全为 `/chat/completions`：

```
https://api.deepseek.com        → https://api.deepseek.com/chat/completions
https://openrouter.ai/api/v1    → https://openrouter.ai/api/v1/chat/completions
https://…/chat/completions      → 原样保留
```

订阅网关（如 opencode）在它的文档里找到 `/v1` 地址粘贴即可，协议是 chat-completions 就能用。

## 五、接口

| 接口 | 说明 |
|---|---|
| `GET /api/settings` | 读取（脱敏），含预设列表、环境变量状态 |
| `POST /api/settings` | `op` 风格：`upsert_provider` / `delete_provider` / `set_active` / `set_general` / `test_provider` / `test_mineru` |
| 测试连接 | 对 chat 端点做一次最小真实调用（返回 延迟/模型/回复）；MinerU 做粘贴完整性检查 + 在线鉴权探测（不创建任务）。Token 形态不限于 JWT，新版 `sk-` 开头的 Key 同样支持 |

## 六、页面入口

- 首页新增「统一设置」按钮
- 树查看器顶栏 ⚙️ 设置；复习页顶栏「设置」
- 上传页：顶部状态条显示当前配置（模型服务 ✓ / MinerU ✓），配置面板的两项输入改为「本次覆盖（可选）」
- 复习页：默认隐藏 Key 输入，显示「✓ 已使用统一配置：DeepSeek（deepseek-v4-flash）」，可展开「本次覆盖」
